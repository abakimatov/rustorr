# R9 — упаковка, безопасность и эксплуатация

Статус: `in progress` с 2026-09-25.

## Цель и решение пользователя

Решение пользователя 2026-09-25: Rustorr разворачивается через Docker на
удалённой машине по SSH. Реестр образов не нужен: образ собирается у
оператора под архитектуру удалённой машины и передаётся по SSH
(`docker save | ssh … docker load`).

Остальное решено под эту цель (пользователь может пересмотреть):

- **Доставка.** `tools/deploy.sh <user@host> <команда>`: `install`/`upgrade`
  (одна команда `deploy`), `status`, `logs`, `backup`, `restore`,
  `rollback`. На удалённой машине нужны только Docker с плагином compose и
  SSH; каталог `~/rustorr` хранит `compose.yaml`, `.env` и бэкапы, данные —
  в именованном томе.
- **Образ.** Обычный (с `ffmpeg` для `/ffp`) и вариант с GStreamer
  (`--gst`); архитектура — по `uname -m` удалённой машины (`buildx`,
  `linux/amd64` или `linux/arm64`). Образ помечается коммитом; предыдущий
  тег сохраняется для отката.
- **Доступ.** Бинарник сохраняет значения по умолчанию MatriX (открыт без
  пароля) и предупреждает в логе, если слушает не-loopback адрес без
  авторизации. Деплой по умолчанию включает `--http-auth` и при первой
  установке создаёт `accs.db` со случайным паролем (выводится один раз).
  TLS — встроенный, как у MatriX (`--ssl`, свой или самоподписанный
  сертификат, `--force-https`), либо внешний reverse proxy
  (`RUSTORR_TRUSTED_PROXIES`).
- **Порты.** HTTP 8090 (и 8091 при TLS), входящие пиры — фиксированный
  порт TCP и UDP (`RUSTORR_PEER_PORT`, по умолчанию 6881), опубликованный
  наружу.
- **Здоровье.** `rustorr health` для `HEALTHCHECK` (в образе нет curl):
  `GET /echo`, код выхода.
- **Бэкап.** `rustorr backup <файл>` — согласованный снимок состояния
  (SQLite через `VACUUM INTO`, `accs.db`, настройки GStreamer,
  сертификаты), без кэша; `rustorr restore <файл>` — в пустой каталог
  данных при остановленном сервере. Деплой делает бэкап перед каждым
  обновлением.
- **Обновление и откат.** Схема только растёт; старый бинарник отказывается
  открывать базу новой версии. Откат — предыдущий образ и бэкап, снятый
  перед обновлением.
- **Логи.** JSON в stdout, ротация драйвера Docker (`json-file`, 10 МБ × 3).
- **Метрики.** Prometheus `/metrics` за авторизацией: торренты, пиры,
  скорости, кэш, HTTP-запросы и их длительность, потоки и задачи HLS.
  Трассировка — спаны `tracing` в JSON-логах, без внешнего экспорта.
- **Совместимость запуска.** Флаги MatriX (`--port`, `--path`, `--httpauth`,
  `--rdb`, `--ssl*` и т. д.) и переменные `TS_*` его Docker-образа как
  алиасы — замена контейнера TorrServer без правки его команды.
- **Секреты.** Ни в образе, ни в логах: пароль прокси, ключи TMDB/Torznab
  в теле запросов access-лога, заголовок авторизации — маскируются.
- Вне R9: импорт каталога данных TorrServer (`config.db`), публикация в
  реестр и CI.

## Порядок

1. **R9.1 — сервер.** `rustorr health`, `backup`, `restore`; предупреждение
   об открытом доступе; аудит секретов в логах.
2. **R9.2 — TLS.** Флаги и поведение MatriX: HTTPS-порт, сертификат из
   флагов или настроек, самоподписанный при отсутствии, `--force-https`.
3. **R9.3 — деплой.** `deploy/compose.yaml`, `deploy/env.example`,
   `tools/deploy.sh`, инструкция.
4. **R9.4 — проверка на «удалённой» машине.** Стенд: контейнер с `sshd` и
   собственным Docker (dind). Smoke: чистая установка, обновление,
   перезапуск, откат, бэкап и восстановление.
5. **R9.5 — метрики, алиасы, допущения.** `/metrics`, флаги и `TS_*`
   MatriX, документ о ресурсах и трафике.

## Критерий выхода

`tools/deploy.sh` разворачивает, обновляет и откатывает Rustorr на
«удалённой» машине по SSH, и это проверяет smoke на стенде; данные
переживают обновление, перезапуск и откат; образы x86_64 и aarch64
собираются одной командой; допущения о ресурсах и трафике записаны;
секретов нет ни в образах, ни в логах; корпуса `direct` и `r7` без
core-различий; `tools/r4.sh check` зелёный.
