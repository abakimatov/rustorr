# Развёртывание на сервере через Docker по SSH

`tools/deploy.sh` ставит, обновляет и откатывает Rustorr на сервере, до
которого есть SSH. Образ собирается на машине оператора под архитектуру
сервера и передаётся по SSH — реестр образов не нужен.

## Что нужно

- **Здесь** (машина оператора): этот репозиторий, Docker с `buildx`, `ssh`
  с доступом к серверу по ключу. Сборка под другую архитектуру (например,
  `x86_64`-сервер с Mac на Apple Silicon) идёт через эмуляцию `buildx` и
  медленнее.
- **На сервере**: Linux `x86_64` или `aarch64`, Docker с плагином
  `compose`, пользователь, которому разрешён Docker (root или группа
  `docker`). Больше ничего.
- **Порты**: HTTP 8090 (и 8091 при HTTPS) — для клиентов; 6881 TCP и UDP —
  для входящих пиров (без него загрузка работает, но медленнее).

## Первая установка

```sh
tools/deploy.sh user@server deploy
```

Скрипт собирает образ, отправляет его, создаёт `~/rustorr` с
`compose.yaml`, `.env` (из `deploy/env.example`) и каталогом `backups`,
заводит HTTP-учётную запись `admin` со случайным паролем и выводит пароль
**один раз**. Адрес для клиентов — `http://server:8090`.

Варианты образа:

- обычный (по умолчанию) — около 180 МБ;
- `--ffprobe` — с `ffmpeg` для `/ffp` (сведения о медиа для некоторых
  клиентов), около 740 МБ;
- `--gst` — с GStreamer: HLS в браузере с выбором звука и субтитров, около
  960 МБ.

Вариант задаётся при каждом `deploy`: обновление без `--gst` заменит
GStreamer-образ обычным.

## Настройки

Все параметры — в `~/rustorr/.env` на сервере; любой флаг `rustorr --help`
задаётся переменной `RUSTORR_*`. После правки:

```sh
tools/deploy.sh user@server restart
```

`.env` скрипт не перезаписывает. Настройки BitTorrent (кэш, трекеры,
поиск, TMDB и т. д.) меняются в веб-интерфейсе и хранятся в данных.

### HTTPS

Встроенный, как у MatriX:

```sh
RUSTORR_SSL=true          # HTTPS на 8091
RUSTORR_FORCE_HTTPS=true  # HTTP отвечает редиректом на HTTPS
```

Без своих файлов Rustorr делает самоподписанный сертификат (браузер
предупредит). Свой сертификат (например, от Let's Encrypt):

```sh
tools/deploy.sh user@server cert fullchain.pem privkey.pem
```

Команда кладёт файлы в том данных (`tls-cert.pem`, `tls-key.pem` с правами
0600), включает HTTPS в `.env`, перезапускает сервер и проверяет, что он
принял сертификат (иначе Rustorr, как MatriX, отдаёт самоподписанный — и
команда сообщает об ошибке). Файлы входят в бэкапы. Продлённый сертификат
ставится той же командой.

### За reverse proxy

Можно не включать встроенный HTTPS, а поставить Rustorr за nginx или Caddy.
Тогда в `.env` — адреса прокси, чтобы ссылки для плееров строились с его
хостом и схемой: `RUSTORR_TRUSTED_PROXIES=172.16.0.0/12`. Если прокси на
том же сервере, HTTP-порт лучше не публиковать наружу:
`RUSTORR_BIND=127.0.0.1` (порт пиров остаётся открытым).

### Доступ

Авторизация включена по умолчанию (`RUSTORR_HTTP_AUTH=true`). Пароль
меняется так (скрипт спросит его):

```sh
tools/deploy.sh user@server password admin
```

Та же команда добавляет новых пользователей. Без авторизации сервер
отвечает всем, кто может к нему подключиться, как MatriX, и пишет об этом
предупреждение в лог. Дополнительно — фильтр по IP и Referer в разделе
«Доступ (WAF)» настроек.

## Обновление и откат

```sh
git pull
tools/deploy.sh user@server deploy
```

Перед обновлением делается бэкап (`~/rustorr/backups/pre-upgrade-*`). Если
новая версия не стала «здоровой», скрипт сам возвращает предыдущую. Вручную:

```sh
tools/deploy.sh user@server rollback
```

Откат сначала запускает предыдущую версию на текущих данных. Если она их
открыть не может (новая версия обновила схему базы), восстанавливается
бэкап, снятый перед обновлением; изменения после обновления теряются.
Сервер хранит два образа — текущий и предыдущий.

## Бэкапы

```sh
tools/deploy.sh user@server backup              # на сервере, в ~/rustorr/backups
tools/deploy.sh user@server download ./backups  # последний — сюда
tools/deploy.sh user@server restore ./backups/manual-….tar.gz
```

Бэкап — база (список торрентов, настройки, «просмотрено», WAF, настройки
GStreamer), учётные записи, `trackers.txt` и файлы HTTPS (самоподписанные
`server.pem`/`server.key` и поставленные командой `cert`). Кэш не входит: торренты докачаются. Файлы бэкапа доступны только
владельцу — в них пароли. Перед восстановлением снимается бэкап текущего
состояния. Бэкапы на сервере скрипт не удаляет.

Без скрипта то же делают команды самого бинарника: `rustorr backup
<файл>` (можно на работающем сервере) и `rustorr restore <файл> --force`
(на остановленном).

## Наблюдение

```sh
tools/deploy.sh user@server status        # образ, состояние, версия
tools/deploy.sh user@server logs --tail 100
tools/deploy.sh user@server logs -f
```

Логи — JSON, по строке на событие, с ротацией Docker (3 файла по 10 МБ).
Пароли, ключи API в телах запросов и адрес прокси с паролем в лог не
попадают. Образ проверяет себя (`rustorr health`), состояние видно в
`status` и `docker ps`.

## Ресурсы и трафик: допущения

Замеры R1–R10 уточнят цифры; до них — порядок величин.

- **Память.** Без нагрузки — около 10 МБ (обычный образ) и 35 МБ (с
  GStreamer). Кэш по умолчанию на диске (`RUSTORR_CACHE=disk`), страничный
  кэш ОС держит недавние куски в свободной памяти. В режиме
  `RUSTORR_CACHE=memory` кэш занимает до `RUSTORR_CACHE_SIZE` ОЗУ. Одно
  перекодирование GStreamer (если включено в настройках) — сотни МБ.
- **Диск.** `RUSTORR_CACHE_SIZE` (по умолчанию 4 ГиБ, мягкий предел:
  просматриваемое не вытесняется) плюс единицы МБ состояния и бэкапов.
- **Процессор.** Отдача файла как есть почти ничего не стоит; HLS без
  перекодирования (перепаковка в fMP4) — лёгкая нагрузка; перекодирование
  видео — тяжёлая, 1–2 vCPU не тянут 4K в реальном времени.
- **Трафик на поток.** Входящий от пиров ≈ битрейт фильма плюс
  3–7 % протокола (фильм 4K HDR — около 25 Мбит/с, ~11 ГБ в час); исходящий
  к зрителю ≈ битрейт (у VPS это платный исходящий трафик). При четырёх
  часах 4K в день — порядка 45 ГБ входящего и 45 ГБ исходящего к зрителю.
  Повторный просмотр из кэша не качается снова.
- **Отдача пирам.** Пока торрент загружен, он раздаётся; ограничения
  скорости и `DisableUpload` из настроек в этой версии не применяются.
  Торрент без зрителей выгружается через `TorrentDisconnectTimeout`
  (30 с), это ограничивает раздачу временем просмотра. На VPS с тарифом за
  трафик это стоит учитывать.
- **Соединения.** Десятки TCP/uTP-соединений с пирами на торрент; при
  публикации порта 6881 — и входящие.

## Что лежит на сервере

```
~/rustorr/
  compose.yaml     # из deploy/compose.yaml, обновляется при deploy
  .env             # настройки, правятся на сервере
  current previous # теги образов
  upgrade-backup   # бэкап последнего обновления
  backups/         # бэкапы (0700)
том rustorr_data   # база, accs.db, кэш, файлы HTTPS
```
