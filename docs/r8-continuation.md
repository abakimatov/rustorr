## R8.1 — каркас

- `web/`: Vite 8, React 19, TypeScript 6 (strict), Tailwind 4 (токены темы в
  `src/styles.css`: светлая по умолчанию, тёмная по системе или
  `data-theme`), TanStack Query, react-i18next (русский и английский, язык
  по браузеру и выбору, тест на совпадение ключей), Vitest, ESLint
  (typescript-eslint strict, react-hooks). TypeScript 7 не взят: typescript-
  eslint поддерживает `<6.1`.
- Клиент API — `web/src/api/`: один `fetch` с `credentials: same-origin`
  (браузер сам добавляет Basic auth), ошибки — `HttpError` со статусом и
  телом.
- Встраивание: `crates/rustorr-http/build.rs` вшивает `web/dist` (или
  `RUSTORR_WEB_DIST`) через `include_bytes!`; без сборки остаётся прежняя
  заглушка корня, и Rust-проверки не требуют Node.
- Отдача (`rustorr-http/src/web_ui.rs`): `/` — `index.html` (`no-cache`),
  `/assets/*` — файлы с хешем в имени (`immutable`, год), файлы корня
  сборки — по своим путям. Всё за HTTP-авторизацией, кроме
  `site.webmanifest`, как у эталона; маршруты только `GET`; неизвестные
  пути по-прежнему получают `404 page not found`.
- `Dockerfile`: стадия `node:24-bookworm-slim` собирает интерфейс на
  платформе сборщика, `dist` копируется в стадию Rust.
- `tools/r4.sh web-check` (и первым шагом `check`): `npm ci` и `npm run
  check` (tsc, eslint, vitest, build) в `node:24`; `node_modules` в
  отдельном томе, чтобы не затирать хостовые нативные модули. `tools/r4.sh
  web <команда>` — любая команда в том же контейнере.

Проверка: `tools/r4.sh check` — 368 Rust-тестов и 5 тестов UI; образ
`docker build .` отдаёт интерфейс, манифест и ресурсы с нужными заголовками.

Прототип одобрен пользователем 2026-09-24.

## R8.2 — шрифты, оболочка, торренты

- Шрифты раздаются вместе с интерфейсом (`@fontsource`, `src/fonts.css`),
  только кириллица и латиница. Для заголовков вместо Bricolage Grotesque
  взят Onest: в Bricolage нет кириллицы.
- Оболочка (`src/app/Shell.tsx`): на десктопе боковая панель с разделами,
  состоянием сервера (`/echo` раз в 30 с), языком и темой (система →
  светлая → тёмная); на телефоне — шапка и нижняя навигация. Маршруты —
  после `#` (`#/`, `#/torrent/<hash>`, `#/search`, `#/settings`), чтобы
  сервер по-прежнему отдавал только `/`.
- Список (`features/torrents/TorrentsPage.tsx`): фильтр по названию,
  фишки «Все / Работают / В базе» и категории, которые есть в списке;
  таблица на десктопе и карточки на телефоне; действия «Смотреть»,
  плейлист M3U, меню «Выгрузить из памяти / Удалить»; плейлист всех
  торрентов. Опрос — каждые 2 с, пока что-то загружено, иначе раз в 10 с.
- Добавление (`AddDialog.tsx`): ссылка или хеш, либо файлы `.torrent`
  (выбор и перетаскивание, каждый — отдельный `/torrent/upload`);
  название, категория, постер, «Сохранить в базе».
- Торрент (`TorrentPage.tsx`): статус, размер, хеш; плейлисты M3U (весь и
  с последнего просмотренного), копирование magnet, выгрузка, удаление;
  статистика раз в секунду; файлы с отметкой «просмотрено», ссылкой для
  внешнего плеера и открытием `/play` в браузере (до плеера R8.3).
  Файлы не загруженного торрента берутся из `data` каталога.
- MatriX опускает нулевые поля статистики (`omitempty`), поэтому у
  загруженного торрента отсутствующие пиры показываются как `0 / 0`.
- Копирование работает и по HTTP в локальной сети: `navigator.clipboard`
  есть только в защищённом контексте, иначе — выделение и `execCommand`.

Проверка: `tools/r4.sh web-check` (14 тестов UI); образ на сети стенда R1
с фикстурами movie, multi, unicode, clip — скриншоты списка, торрента,
меню, диалога добавления и телефонных экранов без ошибок в консоли.

## R8.3 — плеер

- Плеер встроен в страницу торрента: `#/torrent/<hash>/<file>`; кнопка
  «Смотреть» в списке открывает первый воспроизводимый файл. На десктопе
  плеер слева, файлы справа (как в прототипе); на телефоне действия с
  торрентом уходят под плеер.
- Способ воспроизведения (`features/player/media.ts`): напрямую через
  `/play`, если браузер признаёт контейнер (`canPlayType`: MP4, WebM,
  аудио); иначе HLS через `/gst`, если модуль встроен (`GET /gst/settings`
  → `built_in`) и файл — видео; иначе всё равно напрямую (Chromium играет
  многие MKV). Переключатель «Напрямую / HLS» и кнопка «попробовать
  другой способ» при ошибке.
- HLS (`features/player/Player.tsx`): hls.js грузится отдельным чанком
  (575 КБ, 179 КБ gzip) только при HLS; Safari без MSE — нативный HLS.
  Сначала `/gst/<hash>/probe` (дорожки и длительность; сервер кэширует его
  на час и всё равно делает для master), затем
  `master.m3u8?index=<file>&audio=<Index>`. Ожидания загрузки увеличены
  (первый байт — до 120 с): сервер качает из пиров. Звук — выбор из
  аудиодорожек probe; смена перезапускает поток с текущей позиции.
  Субтитры — WebVTT-дорожки master (событие `SUBTITLE_TRACKS_UPDATED`),
  отображаются нативно. Heartbeat `/gst/<hash>/heartbeat` раз в минуту,
  чтобы задачу не заморозили на паузе (сегменты делают то же во время
  игры). `/gst/remove` не вызывается: он выгружает и торрент.
- Позиция: `timecode` в `/viewed` — на первом `playing`, каждые 15 с, на
  паузе и при уходе; конец файла сбрасывает её в 0 и открывает следующий
  воспроизводимый файл. Продолжение — с сохранённой позиции, если она не
  ближе 3 с к началу и не ближе min(10 с, 10 % длительности) к концу;
  плашка «Продолжено с … · С начала». Сервер хранит позицию только при
  включённой настройке `TrackTimecode` (по умолчанию выключена, как у
  MatriX) — переключатель появится в R8.4.
- Эффекты плеера зависят только от примитивов (`useEffectEvent` для
  колбэков): опрос статистики раз в секунду не перезапускает поток
  (`master.m3u8` запрашивается один раз за просмотр).

Исправлено на сервере: сохранённый торрент, выгруженный (`drop` или
таймаут простоя), снова добавлялся по хешу как magnet без трекеров — без
DHT `/play` и `/stream` ждали метаданные бесконечно. Теперь добавление по
хешу или magnet для записи каталога берёт сохранённую метаинформацию, как
MatriX загружает торрент из базы (`LoadTorrent`); тесты в
`rustorr-lifecycle`. Контрактные корпуса после правки: `direct` и `r7` —
0 core-различий (`/tmp/rustorr-contract/r83-direct`, `r83-r7`; эталон из
кэша).

Замечено, не исправлено: probe модуля GStreamer иногда возвращает
субтитры без `Title`/`Language` (в master — «Subtitle 0» вместо
«English»); один раз в консоли был 502 от `/gst`, не воспроизвёлся.

Проверка: `tools/r4.sh check` — 370 Rust-тестов, 17 тестов UI; образ с
`gstreamer` на стенде R1 (сброс трекера и сидера перед запуском, как в
harness): Playwright-сценарий — HLS для MKV (probe → master → init →
сегменты, `master.m3u8` один раз), субтитры, перемотка, сохранение
позиции на паузе и продолжение после перезагрузки, отбрасывание позиции у
конца, прямой режим, аудиофайл, телефон; ошибок в консоли нет.

## R8.4 — настройки и сервис

- `#/settings/<группа>`: кэш и загрузка, просмотр, сеть и трекеры, DLNA и
  Bonjour, поиск (Rutor, индексаторы Torznab с проверкой через
  `/torznab/test`), TMDB — всё это поля `BTSets` (`POST /settings`), у них
  общий черновик на странице (правки переживают переход между группами),
  счётчик изменений и одна кнопка сохранения; «По умолчанию» — `def`, то
  есть сброс всех `BTSets` (отдельных значений по умолчанию API не
  отдаёт), с подтверждением. Перед сохранением UI предупреждает: `set`
  переподключает торрент-клиент и выгружает торренты без зрителей (R6,
  как MatriX).
- Доступ (WAF, `/waf`), GStreamer (`/gst/settings` и состояние
  компонентов из `/gst/echo`; без модуля — сообщение), хранилище
  (`/storage/settings`) сохраняются каждый своим запросом. Предупреждения
  WAF (`invalid_ip_range`, `invalid_referer`) показываются со строкой.
- «О программе»: версия из `/echo`, возможности сборки (HLS из
  `/gst/settings` и `/gst/echo`, ffprobe из `/ffp/status`), остановка
  сервера (`/shutdown`) с подтверждением. На широком экране возможности
  и остановка — в правой колонке, как в прототипе.
- WebDAV в возможностях не показывается: узнать о нём можно только
  запросом к `/dav/`, а `404` выключенного WebDAV браузер пишет в консоль
  как ошибку при каждом открытии настроек.

Найдено при инвентаризации: Rustorr применяет из `BTSets` только кэш
(`CacheSize`, `PreloadCache`, `RemoveCacheOnDrop`,
`TorrentDisconnectTimeout`), ретрекеры (`RetrackersMode`,
`DefaultTrackers`), DLNA/Bonjour, поиск, TMDB, `TrackTimecode`,
`MergeAllM3U`, `ShowFSActiveTorr` и выбор хранилища. Сетью движка
управляют параметры запуска; `ReaderReadAHead`, `UseDisk`,
`TorrentsSavePath`, лимиты скорости и соединений, `PeersListenPort`,
`ForceEncrypt`, `Disable*` (TCP, uTP, UPnP, DHT, PEX, отдача),
`EnableIPv6`, LPD, SSL, `ResponsiveMode`, `EnableDebug`, `TrackersListURL`
только сохраняются. UI показывает их в свёрнутом блоке «Параметры MatriX,
которые Rustorr пока не применяет». Режимы ретрекеров 2 и 3 меняют
magnet-ссылки и список трекеров, но librqbit не убирает собственные
трекеры торрента из анонсов — это сказано в подсказке.

Проверка: `tools/r4.sh check`, 22 теста UI (клиент API настроек, подсчёт
изменений); Playwright на стенде: правки в двух группах → «Изменено 2
параметра» → сохранение, значения подтверждены `GET /settings`; проверка
индексатора стенда (успех с ключом `fixture-key`, «Invalid API Key» и
сетевая ошибка), сохранение индексатора; WAF с неверной строкой →
предупреждение; GStreamer, хранилище, возможности; телефон; остановка
сервера (контейнер завершился с кодом 0). Ошибок в консоли нет.

## R8.5 — поиск и кэш

- `#/search`: запрос, источник (Rutor или Torznab; по умолчанию —
  включённый в настройках), индексатор Torznab (`index`, если их больше
  одного), сортировка по сидам, размеру или дате, «Сохранить в базе».
  Выключенный источник (сервер отвечает `400 []`) — сообщение со ссылкой
  на настройки поиска.
- Результат: название, категория, год, дата, трекер, размер, сиды и пиры;
  «Добавить» отправляет magnet (иначе ссылку на файл) с названием
  раздачи и категорией, выведенной из категории источника (`Movie`,
  `CartoonMovie` → фильмы, `Series` → сериалы, музыка, иначе «Другое»).
  Раздача, чей хеш уже в списке, помечена «Уже в списке» и ведёт на
  торрент.
- Размеры источников — строки; `parseSize` понимает `4.37 GB`,
  `640 MiB`, `12,1 ГБ` и `4.4 GCiB` (так MatriX пишет размеры Torznab;
  контракт повторяет это) — единицы двоичные, по первой букве.
- Карта кэша на странице торрента (под файлами; во время просмотра — в
  правой колонке): `POST /cache` раз в 2 с, пока торрент загружен;
  клетки «в кэше / частично / читается / нет», не больше 600 — куски
  большого торрента складываются в клетки поровну. Заполненность —
  `Filled` из `Capacity`.
- Файлы AC3 и DTS больше не считаются воспроизводимыми в браузере.

Стенд: `rutor.ls` из `tools/contract/r7/fixtures.py` кладётся в каталог
данных до старта; поиск Torznab — индексатор стенда
(`http://indexer:9117`, ключ `fixture-key`); трекер стенда
(`http://tracker:6969/announce`) прописан в «Трекерах по умолчанию», чтобы
magnet без трекеров из результатов получал метаданные — без этого (и без
DHT) добавление ждёт метаданные бесконечно, UI показывает «Добавляем…».

Проверка: `tools/r4.sh check`, 29 тестов UI (размеры, категории,
сортировка, клетки карты); Playwright на стенде: Rutor («Уже в списке»
для раздачи из списка; добавление сериала → торрент в списке с категорией
`tv`), Torznab, сортировка, карта кэша во время просмотра, телефон,
выключенный источник; сценарий плеера R8.3 — без регрессий. Ошибок в
консоли нет.

## R8.6 — завершение

Решение пользователя 2026-09-24: PWA (установка на телефон) и отдельная
работа по доступности в R8 не входят; `site.webmanifest` и иконка
по-прежнему отдаются.

- Перевод: строки интерфейса только через `t()`; тест совпадения ключей
  RU/EN; e2e ищет на каждой странице в обоих языках текст, похожий на
  непереведённый ключ, и проверяет `lang` документа.
- Адаптивность: e2e проверяет отсутствие горизонтальной прокрутки на всех
  страницах на ширинах 390, 768, 1024 и 1440 и на телефоне (Pixel 7).
- Плеер: HLS выбирается по умолчанию, только если браузер декодирует
  H.264 и AAC (MSE или нативный HLS). Несовместимые кодеки (hls.js
  `manifestIncompatibleCodecsError`) раньше глушились попыткой
  восстановления, и плеер молча висел; теперь — сообщение с кнопкой
  «Напрямую» и ссылкой для внешнего плеера.
- Сценарии Playwright в репозитории: `web/e2e/` (`main-path.spec.ts`,
  `pages.spec.ts`), запуск — `tools/r4.sh e2e [аргументы playwright]`.
  `docker-compose.r8-e2e.yml` поднимает на стенде R1 отдельный Rustorr с
  GStreamer (данные в анонимном томе, свежие на каждый прогон; фикстурная
  `rutor.ls`) и раннер `tools/r8/Dockerfile.e2e` (образ Playwright плюс
  `libavcodec60`); трекер и сидер перезапускаются перед прогоном, как в
  harness; лог сервера — `web/e2e/results/rustorr.log`, отчёт —
  `web/e2e/report`.
- Проекты: `desktop` и `phone` (Chromium) — все сценарии; `firefox` —
  основной путь. Chromium из Playwright — открытая сборка без H.264/AAC:
  в нём сценарий проверяет, что плеер сообщает о кодеках, а поток HLS
  (variant, init, сегмент) — по HTTP; Firefox декодирует их через
  libavcodec и проигрывает HLS в браузере. Итог прогона пишется в
  аннотацию `hls` (`web/e2e/results/results.json`).
- Основной путь: добавить magnet через диалог → «Смотреть» → HLS →
  «Напрямую» (`/play`) → M3U торрента (`#EXTM3U`, `link=<hash>`) →
  скопированная ссылка для плеера отдаёт `206` на `Range`. Плюс загрузка
  `.torrent` и аудио (отметка «просмотрено»), поиск Rutor с добавлением,
  настройки (счётчик и отмена изменений). Любая ошибка в консоли роняет
  тест.

## Закрытие R8

Критерий выхода выполнен:
- интерфейс работает только через API R6–R7;
- основной сценарий проходит в Playwright на стенде: `tools/r4.sh e2e` —
  15 сценариев, два прогона подряд без падений; HLS проигрывается в
  браузере (Firefox), нативно — WAV и `/play`;
- корпуса без core-различий: `direct` и `r7` после единственной серверной
  правки R8 (`/tmp/rustorr-contract/r83-direct`, `r83-r7`), `r7-gst` —
  после R8.6 (`/tmp/rustorr-contract/r86-gst`); отложенные различия — в
  allowlist (`r7-root` и прежние);
- проверки UI (tsc, ESLint, Vitest, сборка) входят в `tools/r4.sh check`:
  370 Rust-тестов, 29 тестов UI.

Открытое:
- Большая часть сетевых полей `BTSets` хранится, но не применяется
  (см. R8.4) — отдельная серверная задача.
- Probe GStreamer иногда отдаёт субтитры без названия и языка.
- Добавление magnet без трекеров при выключенном DHT ждёт метаданные
  бесконечно (поведение сервера; в UI — «Добавляем…»).
- Видео в Chromium из Playwright (без проприетарных кодеков) не
  проверяется воспроизведением — только сообщением и по HTTP; Chrome на
  macOS проверен вручную в R8.3.
