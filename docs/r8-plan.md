# R8 — веб-интерфейс на React/Tailwind

Статус: `in progress`. Обновлено: `2026-09-24`.

Цель этапа — новый веб-интерфейс, который управляет Rustorr через уже
перенесённый API (R6–R7) и не меняет ни одного серверного контракта.
Старый интерфейс TorrServer не переносится (решение R7): совпадение
внешнего вида не требуется, возможности — да.

## Решения пользователя (2026-09-24)

- **Воспроизведение в браузере: нативное и HLS.** `<video>` по `/play` для
  форматов, которые браузер умеет, и HLS через `/gst` с hls.js, когда в сборке
  есть модуль GStreamer (Matroska и прочее). Для внешних плееров — M3U,
  прямые ссылки и копирование.
- **Языки: русский и английский.** i18n с самого начала, язык по браузеру,
  переключатель в интерфейсе.
- **Интерфейс вшит в бинарник.** Собранные ресурсы встраиваются при
  компиляции, один файл, как у TorrServer; Docker-сборка получает стадию
  Node.
- **Дизайн предлагаю я.** До реализации — прототип ключевых экранов
  (светлая и тёмная темы, телефон и десктоп) на согласование.

## Инвентарь: что умеет старый UI и чем это закрывается

| Возможность | Старый UI (MatriX.145) | API Rustorr |
| --- | --- | --- |
| Список торрентов | карточки, статус, скорость, пиры, группировка по категориям | `POST /torrents` `list` |
| Добавление | magnet/ссылка/хеш, `.torrent` (drag-and-drop, несколько), название, постер, категория, «сохранить» | `POST /torrents` `add`, `POST /torrent/upload` |
| Поиск | Rutor и Torznab, добавление из результатов | `GET /search/*`, `GET /torznab/search/*` |
| Детали торрента | файлы, размеры, «просмотрено», статистика, данные кэша (карта кусков), ссылки и плейлисты, удалить/выгрузить | `get`, `/viewed`, `/cache`, `/stream`, `/playlist`, `/play` |
| Плеер | встроенный `<video>`, HLS через GStreamer с выбором аудио и субтитров, heartbeat | `/play`, `/gst/*` |
| Внешние плееры | M3U торрента и всех торрентов, копирование ссылок, intent'ы | `/playlist`, `/playlistall/all.m3u`, `/stream?…&m3u` |
| Настройки BitTorrent | все поля `BTSets` (кэш, соединения, DHT/PEX/UPnP, скорость, порт, шифрование, IPv6, DLNA, Bonjour, Rutor, Torznab, ретрекеры и т. д.) | `POST /settings` |
| Настройки модулей | TMDB, индексаторы Torznab (с проверкой), WAF, GStreamer (с `/gst/echo`), хранилище | `/tmdb/settings`, `/torznab/test`, `/waf`, `/gst/settings`, `/storage/settings` |
| Сервис | версия (`/echo`), остановка сервера, «О программе» | `/echo`, `/shutdown` |
| PWA | манифест, установка на телефон | `site.webmanifest` |

Вне R8: Telegram-бот и MCP (отложены за первую версию); OpenAPI-описание
API — R9 вместе с документацией эксплуатации.

## Архитектура

- Каталог `web/`: Vite, React, TypeScript (strict), Tailwind CSS,
  TanStack Query для запросов, react-i18next, hls.js. Никакого серверного
  рендеринга.
- Типизированный клиент API в `web/src/api/` повторяет контракты R6–R7 (типы
  по корпусу и исходникам эталона); это единственное место, где UI знает
  пути и форматы.
- Маршрутизация внутри страницы — через `#`: сервер отдаёт интерфейс только
  на `/`, а неизвестные пути по-прежнему получают `404 page not found`
  эталона. Ресурсы — `/assets/<hash>.<ext>` (неизменяемые, долгий кэш),
  `site.webmanifest` и иконки.
- Всё, кроме `site.webmanifest`, — за HTTP-авторизацией, как у эталона.
- Встраивание: `web/dist` включается в `rustorr-http` при компиляции;
  сборка Rust без собранного UI получает текущую заглушку корня (чтобы
  `cargo test` не требовал Node).
- Проверки: `tsc`, ESLint, Vitest (клиент API, компоненты), Playwright
  (сценарии в браузере против настоящего Rustorr на стенде с сидером);
  всё в контейнерах, как Rust-проверки.

## Порядок работ

1. **R8.0 — план и прототип.** Этот документ; прототип ключевых экранов на
   согласование.
2. **R8.1 — каркас.** `web/`, сборка, линт, тесты, встраивание в бинарник,
   маршруты `/`, `/assets/*`, манифест, стадия Node в `Dockerfile`, проверки
   в `tools/r4.sh check`.
3. **R8.2 — торренты.** Клиент API, список, добавление (ссылка, файлы),
   детали, файлы, удаление/выгрузка, ссылки и плейлисты для внешних плееров.
4. **R8.3 — плеер.** Нативный `<video>`, HLS через `/gst` (аудио, субтитры,
   heartbeat), отметки «просмотрено».
5. **R8.4 — настройки и сервис.** BitTorrent, хранилище, TMDB, Torznab, WAF,
   GStreamer, остановка сервера, «О программе».
6. **R8.5 — поиск и кэш.** Rutor/Torznab с добавлением, карта кусков кэша.
7. **R8.6 — завершение.** Русский и английский полностью, адаптивность,
   сценарии Playwright основного пути. PWA (установка на телефон) и
   отдельная работа по доступности исключены из R8 решением пользователя
   2026-09-24; манифест `site.webmanifest` по-прежнему отдаётся, как у
   эталона.

## Критерий выхода

Интерфейс управляет Rustorr только через API R6–R7; основной сценарий
(добавить торрент, открыть файл, смотреть в браузере — нативно и через HLS,
забрать M3U/ссылку для внешнего плеера) проходит в Playwright на стенде;
корпуса `r7`, `direct` и `r7-gst` остаются без core-различий (кроме
осознанно изменённого `r7-root`); проверки UI входят в `tools/r4.sh check`.
