# R10 — гейты производительности и release candidate

Статус: `in progress` с 2026-09-25.

## Цель

Доказать пользовательское улучшение и функциональный паритет для 1–3
устройств и выпустить воспроизводимый release candidate (раздел R10
[`implementation-plan.md`](implementation-plan.md)).

## Порядок

1. **R10.1 — производительность.** Повторить R1 против текущего Rustorr
   (`RUSTORR_R1_TARGET=rustorr tools/baseline/r1.sh run`, два прогона,
   `aggregate.py` против `docs/benchmark-baseline.json`): p50/p95 холодного
   и тёплого старта, magnet, перемотки (загруженное, отсутствующее,
   вытесненное), непрерывный просмотр 1 и 3 зрителями, задержка с потерями
   (netem), уход пира, CPU/RSS/трафик. Сравнить с эталоном MatriX.145 и с
   R5; отклонение netem из R5 перепроверить на текущем коде.
2. **R10.2 — паритет.** Полные наборы корпусов: `direct`, `auth`, `proxy`,
   `r7`, `r7-gst`, FUSE-проба; e2e интерфейса; smoke развёртывания.
3. **R10.3 — архитектуры.** Бинарник и образ на `x86_64` и `aarch64`:
   сборка обеих, запуск и корпус `direct` против `amd64`-образа (под
   эмуляцией — открытый риск R7).
4. **R10.4 — release candidate.** Версия `1.0.0-rc.1`; воспроизводимые
   артефакты: бинарники обеих архитектур (`.tar.gz` с `SHA256SUMS`),
   образы (`docker save`), проверка повторной сборкой с тем же хешем;
   заметки о выпуске.
5. **R10.5 — бюджет 4 ч/день.** Локально: модель трафика и ресурсов по
   замерам R10.1; затем на VPS пользователя через `tools/deploy.sh` —
   установка, просмотр, метрики `/metrics` и трафик за сеанс.

## Критерий выхода

Все обязательные возможности MatriX.145 доступны на Linux-целях,
существующие клиенты работают без изменений (корпуса), пользовательские
метрики не хуже baseline или отклонения явно приняты, нет необъяснённых
остановок воспроизведения в согласованных сценариях, release-артефакты
собираются воспроизводимо.
